Before you start

Three things to know first

1 · Wake it up

The hosted app sleeps when nobody has used it for a while. If you see a “wake up” screen, click it and wait about a minute. Open it a few minutes before presenting.

2 · Reset first

Click Reset demo data in the left sidebar. It restores the mock systems, empties the approval queues and clears the chats, so the walkthrough starts from the same data every time.

3 · It is shared

Everyone who opens the URL sees the same mock systems and approval queue. If someone else is clicking at the same time, results can mix; Reset puts it right.

Also good to knowWhy
The clock is fixedBusiness date 2026-10-20, SLA clock 10:00. SLA results are the same every time you run the demo.
Planner: rulesThe sidebar shows which planner is running. The hosted demo uses the offline rule-based planner. The Claude planner is built and switches on when an API key is set as a host secret.
Use the step buttonsYou can type your own questions, but the rule planner understands familiar wording best. The numbered buttons send tested messages.

3 · How to read an answer

Every answer carries its evidence

Citations

A citation is [type:id]. It always points at a record a tool actually returned. If an answer contained an ID, date, amount or duration that no tool returned, the grounding check would withhold it.

CitationComes from
[ticket:INC-2008] [user:U001]Service desk (ITSM)
[po:…] [invoice:INV-5102] [sap_user:ASHAV] [vendor:300087] [sap_health:latest]SAP S/4HANA
[contract:CL02]Client contracts (SLA rules)
[cr:CR-502] · [cmdb:…]Change management · CMDB
[msg:MSG-5001] · [approval:ACT-0001]Integration message monitor · the approval queue
[kb:escalation_procedure#4]A runbook and its section number

The status line

Status · response time · trace ID. The same trace ID appears on the Monitoring page.

StatusMeaning
✅ answeredLooked up, cited and grounded.
⏳ pending_approvalAn action was proposed and waits in the queue. Nothing has happened yet.
🚫 deniedAn allowed request, refused by a business rule this time (for example, the ticket is on track).
🛡️ blockedA restricted action. The guard layer refused it and logged the attempt.
⚠️ errorA system was unavailable or sent bad data. The agent says so instead of guessing.
Less common🤷 abstained: no runbook covered it · 🙋 escalated: a ticket was raised for an Orane consultant · ❓ needs_info: say which ticket or invoice · 🛑 guardrail: withheld by the grounding check.

7b · Chaos mode

Show what happens when a system fails

Drag Chaos: API failure rate to the right on any agent page, then click step 1 again. The agent's two mock APIs now fail at that rate with HTTP 500/503 errors, slow replies or malformed data.

You might seeWhat it means
✅ answered, with api_retries 1 or 2A temporary 5xx error or timeout was retried and the call then succeeded. Users see a slower but correct answer.
⚠️ error · “I can't reach…”The system kept failing after 3 attempts, or sent malformed data. The agent stops instead of guessing.
The live view still worksIt reads the mock systems without injected faults, so the audience always sees the real state.

Put the slider back to 0.00 (or click Reset demo data) before moving on.

8 · Approvals

One queue, a named approver, a full audit trail

Everything the agents propose waits here as well as on each agent's page. Nothing is sent, assigned, submitted or reprocessed until a person approves it.

SectionHow to read it
WaitingEach pending action: its ID, what it would do, who must approve it and who asked.
Decidedid ACT-… (agent actions) or APR-… (role requests) · status approved or rejected · by the approver · result the record created: ESC-001 escalation, IA-001 CAB assessment, RP-001 reprocessing run.
Audit logEvery event, newest first: action_requested, action_decided, approval_requested, approval_decided, tool_blocked (a restricted action stopped) and sap_user_unlocked. The audit log is kept when the demo is reset.

9 · Monitoring

The operations view over every turn

Built from the trace of every request. Pick an agent at the top, or leave “All agents”. Hover the small ? icon next to a tile for its definition.

Look atWhat a healthy demo run shows
Latency p50 / p95Tens of milliseconds with the rules planner. Seconds would be normal with Claude.
Error rate · Retries0% with chaos off. They rise when you use the chaos slider, which is the point.
BlockedOne per restricted walkthrough step you clicked (priority change, transport import, payment resend, payment-block release, prompt injection).
Guard hits0: no answer had to be withheld for an ungrounded fact.
CitedClose to 100%: nearly every answer carries a citation.
Outcomes · Tool calls by resultThe mix of answered, pending, denied, blocked and error turns, and which tool produced each.
Recent turnsEach request with its agent, user, intent, status and trace ID. Match a trace ID to the one under an answer.

The traces are kept when the demo is reset, so Monitoring shows the history of the running app. The caption at the bottom of the page lists the designed alert thresholds (errors above 5% over 15 minutes, any guard hit, p95 above 8 seconds, approvals waiting more than 4 hours).

10 · Evaluation

How well each agent did on its test sets

MeasureMeaning
Development setCases the rules were built against. Optimistic by design.
Held-out setSupport desk only: cases written before the rules, kept aside.
Blind setCases written by separate agents that saw only the data and runbooks, never the code, run once without tuning. The honest number.
AccuracyShare of cases with the right outcome: right facts, status, citations and side effects.
Hallucination rateShare of answers containing a fact the tools didn't return, or answering when it should have declined.
Unsafe actions · attempts blockedRestricted actions that took effect (0 everywhere) · unsafe requests the guard layers stopped.
Per-case resultsExpand to see every case, whether it passed, and why not.

How to read the gap: blind accuracy is lower (40–75%) because the rule planners only recognise familiar wording, such as “CR-501” but not “the 501 change”. Every miss failed safe. That gap is the reason for the recommendation: switch on the Claude planner behind the same guard layers, starting with the SLA agent.

11 · Troubleshooting

If something looks wrong

What you seeWhat to do
A “wake up” or blank screenThe hosted app was asleep. Click the wake-up button and wait about a minute.
“Nothing waiting” under approvalsRun step 3 first; that is the step that proposes an action.
Unexpected tickets, approvals or chatSomeone else may be using the shared demo. Click Reset demo data.
“I can't reach one of the systems…”The chaos slider is above 0. Set it back to 0.00.
My own question wasn't understoodThe offline rule planner knows familiar wording. Use an ID (INC-2003, CR-502, MSG-5001) or a walkthrough button.
A step gives a different resultSteps build on each other. Reset, then click the steps in order.
The hosted app is downRun it locally with run_demo.bat or sh run_demo.sh, or print the same flows with python demo_script.py.

Glossary

TermMeaning
AMSApplication management services: running and supporting a client's SAP systems.
CABChange advisory board: the group that approves production changes.
CMDBConfiguration management database: which objects, applications and interfaces depend on each other.
IDocSAP's interface document; status 51 means it failed to post.
Guard layerThe code between the planner and the systems that decides whether each tool call may run.
Grounding checkThe check that every fact in an answer came from a tool result.
PlannerThe part that chooses which tools to call: rules (offline) or Claude.
TraceThe record of one request: tools called, status, latency, citations, with personal data masked.
